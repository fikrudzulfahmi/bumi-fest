## Keputusan & asumsi
- Tailwind 4 + Tailwind CSS Vite plugin (bukan v3).
- Folder `resources/js/{Components,Layouts}` huruf besar (Breeze default).
- Enum cast di User model untuk type safety.
- F02: status dihitung per lomba (Dibuka|Segera dibuka|Ditutup|Kuota penuh) via computeStatus(now). Scope published/forLevel untuk query N+1-free. withoutVite() di test (bypass manifest build). Nullable quota=null → kuota unlimited. Match expression di Policy > enum comparison (PHPStan safe).
- F03: hapus lomba cek `DB::table('registrations')` + guard `Schema::hasTable` (tabel registrations baru ada di F05). PDF juknis di disk `public` (`competitions/rules/`, nama acak) — publik karena juknis memang untuk peserta. Duplikat = replicate() + slug `-salinan[-N]`, status draft, results_published_at null. Belum ada nested entries/scores untuk disalin, jadi seluruh kolom ikut tersalin.
- F03: `Edit.tsx` masih stub (menampilkan nama lomba) — form edit penuh dikerjakan bersama F05 saat field submission/dokumen benar-benar dipakai.
- F06: impor dua langkah — pratinjau hanya cache (token 30 menit, `Cache::put`), komit pakai `DB::transaction` + `lockForUpdate` pada lomba sehingga kuota tak bisa lewat walau dua sekolah komit bersamaan. Baris Excel dibaca via `rangeToArray` (bukan `getRows()` yang tidak ada di PhpSpreadsheet). Larastan salah baca enum cast `role`, jadi pola `abort_unless($user->role === Role::Institution)` di-ignore di `phpstan.neon`, bukan diubah jadi perbandingan string (runtime tetap enum yang benar).
- F06: siswa dicocokkan per `owner_id + nama + kelas` — satu siswa boleh ikut beberapa lomba, tapi tidak boleh dua entri di lomba yang sama (ditandai error baris di pratinjau).
- F07: rute `/tagihan/{invoice}` & `GET /tagihan/{invoice}/bukti` sengaja di grup `auth,verified` tanpa `role:*` — admin juga perlu melihat tagihan peserta; otorisasi lewat `InvoicePolicy` (`view` pemilik/Admin, `verify`/`reject`/`extend` Admin saja). Rute `/tagihan` (index), `POST bukti`, dan seluruh `/admin/pembayaran*` tetap pakai `role:participant,institution` / `role:admin`.
- F07: bukti disimpan di disk `local` (`invoices/{id}/`), hanya disajikan lewat rute ber-otorisasi (`StreamedResponse`), tidak pernah lewat URL publik.
- F07: kode unik tetap satu-satunya pembeda nominal (BR-07), ditampilkan + tombol salin di UI pengguna. Nominal transfer tidak divalidasi otomatis (verifikasi manual admin, sesuai spec).
- F07: expire hanya menyentuh `unpaid` & `rejected` — tagihan `awaiting_verification` yang lewat jatuh tempo TIDAK dikadaluarsakan agar bukti yang sudah diunggah tetap bisa diverifikasi admin.
